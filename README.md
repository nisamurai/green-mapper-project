# GreenMapper

Процесс разработки

Используем GitHub Flow. Для задачи создаём рабочую ветку от актуальной main. Изменения оформляем коммитами и открываем pull request в main. Другой участник просматривает изменения и отправляет одобрение. Затем руководитель выполняет слияние merge-коммитом. Прямые изменения main после первоначальной инициализации не допускаются.

Ветки называются feature/gm-000-description, docs/gm-000-description или chore/gm-000-description. Сообщения коммитов имеют вид type(scope): описание. В теле указываются Issue, требования FS и пункты HLD, относящиеся к изменению.

У каждой задачи есть ответственный, описание результата, критерии приёмки и зависимости. Статусы доски: Todo, In Progress, In Review, Done. Зависимая задача не запускается до выполнения нужных предшественников.

Карточка функции получает Done, когда код влит в main через одобренный PR, выполнены указанные требования FS, проект собирается и запускается, затронутые ранее доступные функции работают. В карточке документации проверяются содержание, ссылки и согласованность с проектом. Если код не менялся, проверка приложения по этой задаче не требуется.

Все участники выступают авторами и ревьюерами. Руководитель проверяет PR остальных участников. PR руководителя проверяет другой участник. GM-001 проверяет @Egor79437658, GM-002 @nimitzer, GM-003 @IghorTatar, GM-004 @DrobchikAV, GM-005 @DashaSmir.
