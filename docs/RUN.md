Запуск GreenMapper

Нужны Docker Engine с Compose и доступ к образам. Для локальных команд разработки используются Bun и Python. Команды выполняются из корня проекта.

1. Скопируйте .env.example в .env. Задайте собственные пароли PostgreSQL, Redis, RabbitMQ и MinIO, имя БД, имя бакета и BETTER_AUTH_SECRET. Файл .env не добавляется в Git.
2. Для доступа через Caddy согласуйте BETTER_AUTH_URL, CORS_ORIGIN и переменные VITE_BETTER_AUTH_BASE_URL, VITE_API_BASE_URL, VITE_MINIO_BASE_URL. Браузер должен обращаться к адресу приложения, а не внутренним именам Docker-сервисов. CADDY_PROXY_URL указывает внутренний адрес backend.
3. Проверьте конфигурацию без вывода значений: docker compose config --quiet. Затем выполните docker compose up --build -d. Если порт 80 занят, измените внешний порт frontend и соответствующие адреса окружения.
4. Проверьте docker compose ps. GET http://localhost:3000/health должен вернуть status ok. Клиент открывается через опубликованный порт frontend. Миграции и справочники применяются при запуске backend.
5. Для настоящей проверки изображений поднимите Ollama через docker compose -f ai_compose.yml up -d. В конфигурации предусмотрен GPU. При отсутствии совместимого GPU уберите параметр gpus в локальной конфигурации. Загрузите модель, указанную в OLLAMA_MODEL, командой docker exec ollama ollama pull ИМЯ_МОДЕЛИ. OLLAMA_HOST должен быть доступен worker из его контейнера, например через host.docker.internal и опубликованный порт Ollama. Для настоящей проверки SKIP_LLM не должен быть true.
6. Для второго фактора задайте SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS и SMTP_FROM. Проверьте доставку письма реальным входом. Для входа через Яндекс задайте YANDEX_CLIENT_ID и YANDEX_CLIENT_SECRET и разрешите адрес возврата в настройках приложения Яндекс ID.

Демонстрационные данные

Скрипт backend/scripts/seed-demo.ts создаёт пять локальных учётных записей: DemoUser, DemoReader, DemoOperator, DemoAdmin и DemoSuper. Адреса имеют вид demouser@example.invalid. Пароль берётся только из DEMO_PASSWORD. DemoReader и DemoSuper получают доступ к опасному контенту. Для двух пользователей создаются заявки пяти статусов, включая заявку с признаком опасного контента.

Перед наполнением остановите worker, чтобы модель не изменила демонстрационные статусы: docker compose stop worker. Не останавливайте backend, БД и хранилище.

В PowerShell задайте DEMO_PASSWORD для текущего процесса и выполните из каталога backend:

```powershell
bun --env-file=../.env scripts/seed-demo.ts
```

Скрипт использует опубликованные порты backend и БД. Для другого адреса API задайте DEMO_API_URL. Повторный запуск пропускает уже созданные демонстрационные заявки. Существующие данные не удаляются. Пароль существующих аккаунтов должен совпадать с DEMO_PASSWORD.

После наполнения запустите worker командой docker compose start worker. Для показа состояния На валидации его можно оставить остановленным, затем отдельно показать переход после запуска обработки.

Проверка

- Гость видит карту и доступные публичные карточки.
- Пользователь создаёт заявку из точки карты, видит свои заявки и баллы.
- DemoReader видит фильтр опасного контента.
- DemoOperator завершает заявку из В работе, администратор меняет разрешённые статусы.
- DemoSuper находит пользователя и меняет роль и доступ.
- Ошибки SMTP, модели и очереди проверяются отдельно от обычного успешного сценария.

Остановка: docker compose down. Томами с данными управляют отдельно. Не выполняйте удаление томов для обычной остановки.
